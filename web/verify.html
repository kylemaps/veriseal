veriseal independent verifier

Drop a sealed log (.mcap) and its .seal.json manifest. This page recomputes the signature, the Merkle root, and the file digest entirely in your browser — nothing is uploaded.

Why this matters You are checking the evidence yourself, without trusting the operator who produced the log or the tool that sealed it. A green VERIFIED requires you to pin the signer's key (below): only then does it mean the log matches a seal made by that specific signer — proved on your own machine. Without a pinned key the result stays amber, because anyone could re-seal a tampered log with their own key.
Paste the signer's public key, obtained out-of-band (not from this file), to pin authenticity. Without it, a tampered log re-signed with a new key would still look valid — so a genuine-looking seal stays amber, never green, until you pin the key.

Verification runs client-side with the WebCrypto API (Ed25519 + SHA-256). Open the source: this file has no network calls.
Signature — the manifest is authentic to its Ed25519 key. Merkle root — the listed message hashes fold to the signed root. File digest — the log's bytes match what was sealed; any change flips this.
Signer key pin — paste the signer's public key (obtained out-of-band) into the field above. A green VERIFIED requires it; without it the result stays amber, because the embedded key alone proves nothing about who signed.
